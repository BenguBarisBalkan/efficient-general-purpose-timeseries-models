# Zero-shot (cross-dataset transfer) forecasting — SparseTSF and TimeMixer

Train on dataset **A**, evaluate on unseen dataset **B** with no further training, over the 6 ETT
transfer pairs. `seq_len=96`, `pred_len ∈ {96,192,336,720}`, MSE/MAE. Generated by
`benchmarks/run_zeroshot_benchmarks.py` (idempotent).

- Implemented by training on A, copying A's checkpoint into B's `setting` directory, then running B
  with `--is_training 0` (test-only). The model never sees B's training data.
- SparseTSF's linear layer has shape `(seq_len/period_len → pred_len/period_len)`, so the **source**
  dataset's `period_len` is reused for the target — otherwise the checkpoint would not load. All
  `pred_len`s here are divisible by both 24 and 4, so every pair is valid.
- **SparseTSF and TimeMixer are both run locally**, same machine and same protocol. TimeMixer uses
  the source dataset's own long-term configuration (`benchmarks/tm_config.py`) for training and for
  the target test, mirroring the `period_len` rule above. The *published* TimeMixer / TimeMixer++
  columns (TimeMixer++ paper, ICLR'25, Table 6) are in italics as reference points.
- The local TimeMixer run lands close to its published figures (mean MSE 0.448 locally against 0.467
  published), so the local protocol is a fair stand-in. **SparseTSF beats the local TimeMixer on all
  six pairs** (mean MSE 0.393 against 0.448); the largest margins are on ETTh2→ETTh1 (0.453 vs 0.639)
  and ETTm1→ETTh2 (0.396 vs 0.464).
