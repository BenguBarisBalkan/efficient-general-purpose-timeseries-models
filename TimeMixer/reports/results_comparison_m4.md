# M4 univariate short-term forecasting — SparseTSF and TimeMixer

Six M4 subsets (Yearly/Quarterly/Monthly/Weekly/Daily/Hourly), input length = 2×horizon, metrics
averaged across subsets. Lower is better for all three. Generated by
`benchmarks/run_m4_benchmarks.py` (idempotent); OWA uses `dataset/m4/submission-Naive2.csv`.

- **SMAPE** — symmetric MAPE; **MASE** — mean absolute scaled error; **OWA** — overall weighted
  average (the M4 competition's headline metric; 1.0 = the Naive2 baseline).
- SparseTSF config: 10 epochs, batch 16, loss SMAPE, `lr=0.01`, per-subset `period_len`
  {Y2,Q4,M6,W13,D7,H24} (each divides its subset's horizon and `seq_len = 2×horizon`).
- TimeMixer config: copied verbatim from upstream `scripts/short_term_forecast/M4/TimeMixer.sh`
  (4 layers, d_model 32, batch 128, `lr=0.01`, 50 epochs, patience 20, loss SMAPE).
- **SparseTSF and TimeMixer are both run locally**, same machine. The local TimeMixer reproduces its
  published result almost exactly (OWA 0.841 against 0.840), so the local comparison is sound:
  SparseTSF is 15.6% behind TimeMixer on OWA (0.972 against 0.841). TimeMixer++ is the *published*
  value from the TimeMixer++ paper (ICLR'25, Table 2), in italics.
