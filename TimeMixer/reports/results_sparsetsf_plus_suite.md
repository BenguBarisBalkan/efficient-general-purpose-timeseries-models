# SparseTSFPlus across the 8-task suite

SparseTSFPlus in two versions beside the locally run SparseTSF and TimeMixer, on every task and
dataset of the TimeMixer++ protocol that is obtainable here. Generated by
`benchmarks/run_sparsetsf_plus_suite.py` (idempotent).

- **SparseTSFPlus (fixed)** is **one configuration for everything**, the thesis's target form:
  learned-trend decomposition (forecasting) and phase mixing (every task that folds the series into
  periods) in the backbone; gated refinement and mask-aware aggregation whenever the input has
  missing values; default heads otherwise. This is the headline version.
- **SparseTSFPlus (per task)** uses the unit set that won each task in the ablations, unchanged across
  that task's datasets. It shows what per-task choice adds, so the gap between the two columns is
  the current cost of generality.
- Both use SparseTSF's own published period for every dataset, except the per-task PEMS cell (the
  ablation's phase mixing at period 4). All other training settings are SparseTSF's, so each row
  differs from SparseTSF only in the units.
- **Reused cells** (identical runs already existed): imputation, both versions, are the ablation's
  `allrg` and `u5g` variants (gated refinement); classification, both versions, is the ablation's
  default head (no unit applies to it), so it equals SparseTSF up to run-to-run noise; per-task
  PEMS is the ablation's `phase_p4`; per-task anomaly detection has no units and is SparseTSF
  itself.
- A dataset's mean needs all of its horizons or mask rates, and a task's mean covers only the rows
  where every column has a value. Lower is better except for F1 and accuracy.
- Imputation, anomaly detection and classification early-stop on test (upstream behaviour shared
  by every model), so read those rows as a sensitivity analysis.

```bash
venv/Scripts/python.exe benchmarks/run_sparsetsf_plus_suite.py
```

## Findings

All runs use one seed, so differences below about 1% are not findings on their own.

- **One configuration costs almost nothing outside imputation.** The fixed version is within 0.4%
  of the per-task version on every other task, and slightly ahead on long-term forecasting, M4 and
  PEMS.
- **Imputation: gated refinement, and the one remaining gap.** Both versions now use refinement
  behind a learned gate (see the imputation ablation), which improved them by 7.4% (fixed) and 9.1%
  (per task). The fixed version is 5.8% behind the per-task one, and all of that comes from phase
  mixing, which the fixed backbone keeps because PEMS needs it. It costs 20.1% on ETTh2 and 10.5% on
  Electricity imputation and is within ±1.2% on the other four. A gate on phase mixing did not
  remove that cost.
- **Against SparseTSF, the fixed version improves or matches every task:** PEMS −25.4%, imputation
  −17.8%, M4 OWA −6.0%, few-shot −2.0%, long-term −1.8%, zero-shot −0.4%. Anomaly detection and
  classification are unchanged: phase mixing moves anomaly F1 by 0.02 points while raising the
  model from 41 to 666 parameters, and no unit applies to the classification head.
- **Against TimeMixer (local)** the fixed version wins few-shot (−12.1%), zero-shot (−12.7%) and
  anomaly detection (+4.5 F1 points, carried by MSL). It loses long-term forecasting (+8.4%), M4
  (+8.7%), PEMS (+45.3%), imputation (+10.8%) and classification (−1.5 points). On long-term
  forecasting it beats TimeMixer on both hourly ETT datasets and trails on the rest, most on Solar.
- **Size.** The fixed version stays between 37 and 8,661 parameters outside classification
  (classification is SparseTSF's own head, 3,142–970,712), against TimeMixer's tens of thousands
  to millions.
- **Energy** (matched protocol, same session for SparseTSF, SparseTSFPlus and TimeMixer). The
  fixed version uses 1.35× SparseTSF's energy (per task 1.33×), so its units cost about a third
  more energy. TimeMixer uses 18.9× SparseTSF's, which is 14× the fixed SparseTSFPlus. Measurement
  caveat: SparseTSF's same-session total is 42% below its July value, while TimeMixer's moved only
  5%. Runs of 10–20 s are dominated by fixed overheads that vary between sessions, so only
  same-session ratios are reliable. By that measure the July table's SparseTSF/TimeMixer ratio
  (8.7%) overstates SparseTSF's cost; the same-session ratio is 5.3%.
